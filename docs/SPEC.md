# Laminat — контракт v1

Нативное macOS-приложение для просмотра Parquet-файлов. Главный принцип — скорость:
только AppKit/Swift, никаких Electron/WebView-интерфейсов (кроме HTML-превью в Quick Look, где это стандартный путь).

Многие решения в v1 намеренно простейшие. Всё, к чему надо вернуться, собрано в разделе 6 и в [IDEAS.md](IDEAS.md).

## 0. Рамки v1

| | Решение |
|---|---|
| Платформа | macOS 15+, Apple Silicon и Intel |
| Форматы | только Parquet, один файл (без папок и партиций) |
| Размер файла | до ~1 ГБ — целевой и тестовый максимум; больше должно работать, но не оптимизируется |
| Дистрибуция | GitHub Releases, ad-hoc подпись без Apple Developer ID (см. §5) |

## 1. Режимы

### 1.1 Quick Look (пробел в Finder)

Минимум функционала, максимум скорости открытия.

- Шапка: имя файла, число строк, число колонок, размер файла.
- Схема: список колонок с типами данных (`INT64`, `VARCHAR`, `TIMESTAMP`, `DECIMAL(18,2)`, `STRUCT<…>` и т. д.).
- Данные: таблица с заголовками колонок и первыми строками.
  - Если таблица маленькая (≤ 1000 строк и ≤ 50 000 ячеек), рисуется целиком.
  - Иначе первые 100 строк и подпись «показано 100 из 12 345 678».
  - Не больше 100 колонок («показано 100 из 501 колонки»). Чтобы получить первую строку, нужно распаковать
    первую страницу каждой колонки, поэтому память растёт с числом колонок: 500 колонок не влезали в 512 МБ.
- Длинные значения обрезаются до 200 символов, бинарные показываются как `<binary 1.2 KB>`,
  вложенные типы — однострочным JSON, `NULL` — приглушённым цветом.
- Без интерактива: ни сортировки, ни фильтров, ни SQL.
- Битый или не-Parquet файл — понятное сообщение об ошибке вместо пустого окна.

Бюджет: превью появляется ≤ 300 мс (читаются только footer и первая row group).

### 1.2 Миниатюра в Finder (Thumbnail extension) — готово

Иконка `.parquet`-файла в Finder и в Quick Look — мини-таблица: синяя шапка с именами первых колонок
(примерно одна колонка на 60 pt ширины), до 12 строк «зеброй», `NULL` приглушён, бейдж «parquet». На мелких
размерах рисуется только сетка. Читается footer и начало первой row group: 16–40 мс на файл (первый вызов
после запуска расширения ~1,7 с), в том числе на файле 1,7 ГБ.

### 1.3 Spotlight — заблокировано

Хотели индексировать имена колонок, чтобы файл находился поиском по колонке. Сделано расширение
`CSImportExtension` (`Spotlight/`), Spotlight его видит (`mdimport -e`), но:
- при обычной фоновой индексации Spotlight его ни разу не вызвал (файлы получают только базовые атрибуты,
  «imported with no plugIn»), в том числе после перевода UTI в exported;
- при ручном вызове (`mdimport -m`) расширение запускается, но песочница не даёт ему увидеть файл
  (`exists=false`, security-scoped доступ не помогает).

Пока расширение собирается, но не встраивается в приложение. Варианты — см. раздел 6 (Q16).

### 1.4 Просмотр (двойной клик / «Открыть с помощью»)

Одно окно на один файл (document-based app).

- **Таблица данных**
  - Виртуализированный грид: рисуются только видимые строки, данные подгружаются страницами по мере скролла.
  - Скролл до любой позиции, в том числе в конец, без загрузки промежуточных данных.
  - Ресайз колонок, закреплённый заголовок, номер строки слева.
  - Выделение ячеек/строк, копирование в буфер (TSV), «копировать значение».
  - Отображение наивное: значения как отдаёт движок, вложенные типы — однострочный JSON,
    `NULL` — приглушённым цветом.
- **Сортировка** — по одной колонке, клик по заголовку: asc → desc → сброс.
- **Фильтр** — поле над каждой колонкой, фильтр «содержит» (без учёта регистра, по текстовому
  представлению значения). Фильтры по разным колонкам объединяются через AND.
  В статус-баре: «1 234 из 12 345 678 строк».
- **Панель схемы**: колонки, типы, nullable; метаданные файла (row groups, сжатие, создатель файла).
- **Статус-бар**: число строк, время последней операции, индикатор фоновой загрузки.

### 1.5 SQL-режим

Вкладка SQL в окне документа (переключатель «Data | SQL» в тулбаре, ⌘1 / ⌘2): редактор сверху, результат
снизу. Фильтры и сортировка основного грида на SQL не влияют и наоборот.

- Таблица доступна под двумя именами:
  - **имя файла без расширения**: `sales_2024.parquet` → `SELECT * FROM sales_2024`
    (невалидный идентификатор — в кавычках: `"my data-v2"`);
  - **алиас `t1`**. Когда появятся несколько файлов (IDEAS.md), они получат `t2`, `t3`, … в порядке открытия.
- **Несколько файлов**: слева панель «Tables» — таблицы окна (сам файл = `t1`) с колонками и типами.
  ＋ или перетаскивание .parquet из Finder на панель / редактор добавляет файл как `t2`, `t3`… и под именем
  файла (при совпадении — `name_2`); при бросании в редактор имя вставляется в место бросания. Двойной клик
  вставляет имя таблицы / колонки; автодополнение знает все таблицы. Набор таблиц — на время жизни окна.
- Результат сохраняется во временную таблицу DuckDB (не больше 1 млн строк, иначе пометка «result truncated»)
  и показывается в том же виртуализированном гриде: ленивая подгрузка, сортировка, фильтры, копирование.
- Выполняется одно выражение за раз (выделенный фрагмент или весь текст).
- Запуск по ⌘↩, выполнение в фоне, отмена (⎋ / Stop), время выполнения и число строк.
- Ошибки SQL выводятся под редактором с позицией, если движок её отдаёт.
- Редактор: моноширинный шрифт, подсветка синтаксиса, история запросов в рамках сессии (между запусками не
  сохраняется). Автодополнение колонок — желательно, не блокер.
- Только чтение: DuckDB разбирает запрос, и выполняется только выражение типа SELECT (включая `WITH`,
  `DESCRIBE`, `SUMMARIZE`, `SHOW`). `COPY … TO`, `ATTACH`, `INSTALL`, `CREATE` и прочее отклоняются до выполнения.
- Автодополнение по ⎋ / F5: колонки, имя таблицы, ключевые слова.
- **Шаблоны частых запросов**: палитра (⌘⇧T; ⌘T — новая вкладка, как в Finder) со встроенными шаблонами. Шаблон подставляется в редактор с
  уже вписанной таблицей и плейсхолдерами (`⟨column⟩`) для перехода по Tab. Стартовый набор:
  - первые N строк: `SELECT * FROM t1 LIMIT 100`;
  - число строк: `SELECT count(*) FROM t1`;
  - топ значений: `SELECT ⟨column⟩, count(*) AS n FROM t1 GROUP BY 1 ORDER BY n DESC LIMIT 50`;
  - дубликаты по ключу: `… GROUP BY ⟨key⟩ HAVING count(*) > 1`;
  - пропуски по колонке, распределение по датам (`date_trunc`), случайная выборка (`USING SAMPLE`).

### 1.5.1 Экспорт

**File → Export To → CSV… / Parquet… / JSON Lines…** (как в Numbers и Pages), а также «Export…» в
контекстном меню грида. Выгружается то, что показывает текущая вкладка: файл с применёнными сортировкой и
фильтрами (в порядке вида) или результат SQL. Все колонки, полные значения и исходные типы (`COPY … TO` в
DuckDB, а не строки из грида). Идёт в фоне с оверлеем и отменой; недописанный файл при ошибке или отмене
удаляется. Замер: отфильтрованный вид — 1,2 с, отсортированные 30 млн строк в Parquet — 26 с (2,7 ГБ).

### 1.6 Статистика по таблице

Вкладка **Stats** в тулбаре окна (⌘3): таблица-профиль всех колонок (одна колонка файла = одна строка),
под ней детали выбранной колонки. Расчёт стартует при открытии вкладки:

- для всех типов: тип, число и % пропусков, число уникальных значений;
- для чисел: min, max, среднее, медиана, стандартное отклонение, p25/p75;
- для строк: min/max длина, топ-5 значений;
- для дат и времени: min, max.

- Уникальные значения, медиана и квантили — **приближённые** (`approx_count_distinct`, `approx_quantile`),
  в интерфейсе помечены «≈». Точный расчёт — позже, отдельной кнопкой.
- То, что есть в метаданных Parquet (число строк, null count, min/max), показывается мгновенно,
  остальное досчитывается в фоне с прогрессом и отменой.
- Считается по всему файлу или по отфильтрованным строкам (переключатель).
- Профиль сортируется по любой метрике, колонки ищутся по имени, ⌘C копирует строки как TSV.
- Детали выбранной колонки (считаются по клику): гистограмма (числа, даты; для строк — распределение длин;
  целые значения в узком диапазоне — по корзине на значение) и топ-10 значений с долями. Кнопка
  «Open in SQL» открывает запрос с топом значений во вкладке SQL.
- Замер: профиль 10 колонок × 30 млн строк — 1,6–1,7 с, детали колонки — 0,1–1 с.

## 2. Нефункциональные требования

| Метрика | Цель (файл до 1 ГБ) |
|---|---|
| Quick Look, первый показ | ≤ 300 мс |
| Миниатюра | ≤ 100 мс |
| Холодный старт до первой страницы данных | ≤ 500 мс |
| Скролл | 60/120 fps, без фризов главного потока |
| Сортировка / фильтр | ≤ 1–2 с, UI не блокируется, отмена |
| Статистика | ≤ 5 с, колонки появляются по мере готовности |
| Память | не растёт линейно с размером файла |
| Размер бандла | ~112 МБ в распакованном виде, ~35 МБ zip (почти всё — универсальная `libduckdb.dylib`) |

Для файла в 1 ГБ это реалистичный запас: DuckDB читает Parquet такого размера за секунды, а для просмотра
читает только нужные row groups.

## 3. Архитектура

- **Движок: DuckDB** (in-process, C API). Готовая универсальная `libduckdb.dylib` из релизов DuckDB, версия
  и контрольная сумма зафиксированы в `scripts/fetch-duckdb.sh`. Библиотека лежит в `Contents/Frameworks`
  приложения, расширения подгружают её оттуда же. Swift-пакет `duckdb-swift` не используем: он отстаёт от
  релизов и компилирует DuckDB из исходников, что сильно тормозит сборку. Нативно читает Parquet с projection/predicate
  pushdown и пропуском row groups по статистике. Один движок обслуживает просмотр, сортировку, фильтры,
  статистику и SQL.
- **UI**: AppKit, document-based (`NSDocument`): двойной клик в Finder открывает файл в окне.
  Грид — view-based `NSTableView` с ячейками, которые рисуют текст сами (без `NSTextField` и Auto Layout).
  Фильтры — поля в нижней строке шапки таблицы. SwiftUI допустим только для второстепенных панелей.
- **Подгрузка данных** (`App/Data/TableSession.swift`):
  - кэш «страница × колонка»: читаются только видимые колонки (с запасом в 2 по краям), остальные
    догружаются при горизонтальной прокрутке. Время уходит на декодирование тяжёлых колонок, а не на число
    строк, поэтому это главный рычаг;
  - без сортировки и фильтра страница — 1000 строк по диапазону `file_row_number`;
  - сортировка или фильтр строят индекс-таблицу `(позиция → file_row_number)` по одной колонке-ключу,
    страница — 5000 строк по номерам (цена почти не зависит от числа строк);
  - отдельные соединения и очереди для страниц и построения вида; новая сортировка прерывает старую;
  - LRU-кэш ~5 млн ячеек, сначала видимые страницы, потом соседние; пролистанные страницы не читаются.
  - Замеры (`laminat-cli bench`), 30 млн строк / 501 колонка:

    | | все колонки | видимые |
    |---|---|---|
    | страница, обычный вид | 112 / 398 мс | 31 / 8 мс |
    | страница, сортировка | 218 / 792 мс | 111 / 35 мс |
- **Память**: лимит DuckDB в приложении — 50 % RAM (по умолчанию 80 %). Сортировка 30 млн строк даёт
  кратковременный пик ~2–4 ГБ (параллельная сортировка), после неё остаётся ~0,9 ГБ, в основном сам индекс.
- **Quick Look / Thumbnail / Spotlight**: общий модуль `Shared`. В песочнице расширений: автозагрузка
  расширений DuckDB отключена, временные файлы — в контейнер, `threads=1`, `memory_limit=512MB`. HTML-превью для
  Quick Look. Если HTML окажется медленным на 1000×50, перейти на view-based превью с `NSTableView`.
- **Модули**: `Shared/Engine` (DuckDB, страницы, отмена, регистрация таблиц), `Shared/Model` (схема, типы,
  форматирование значений), `App` (окна, грид, SQL-редактор, статистика), `QuickLook`, `Thumbnail`, `Spotlight`.
- Главное приложение без песочницы (не App Store). Quick Look и Thumbnail extensions в песочнице: этого требует система.

### 3.1 Замеры Quick Look (M-серия, `laminat-cli preview`, прогретый кэш)

| Файл | Размер | Время | Пик памяти |
|---|---|---|---|
| `samples/types.parquet`, 50 строк, вложенные типы | 6 КБ | 6–20 мс | 34 МБ |
| 30 млн строк, 10 колонок, zstd | 1,7 ГБ | 90 мс | 230 МБ |
| 200 тыс. строк, 501 колонка (показано 100) | 475 МБ | 75 мс | 150 МБ |

Почти всё время уходит на чтение первой row group. В больших файлах память определяется размером колонок
в первой row group, а не размером файла.

## 4. Вне скоупа v1

Вкладки, запросы по нескольким файлам, сохранённые запросы и пользовательские шаблоны, экспорт,
папки и партиции, другие форматы, редактирование данных, сетевые источники. См. [IDEAS.md](IDEAS.md).

## 5. Дистрибуция

- Сборка в GitHub Actions (или локально скриптом): `.app` в `.zip`/`.dmg`, публикация в GitHub Releases.
- Подпись ad-hoc (`codesign -s -`), без нотаризации: Apple Developer ID ($99/год) не нужен.
- Установка у коллеги:
  1. скачать и распаковать, перенести `Laminat.app` в `/Applications`;
  2. запустить — macOS заблокирует запуск;
  3. System Settings → Privacy & Security → «Open Anyway» (на macOS 15 обход через правый клик → «Открыть»
     больше не работает, только через настройки). Альтернатива для тех, кто дружит с терминалом:
     `xattr -dr com.apple.quarantine /Applications/Laminat.app`;
  4. запустить приложение один раз, чтобы зарегистрировались Quick Look, миниатюры и Spotlight;
  5. проверить, что расширение включено: System Settings → General → Login Items & Extensions → Quick Look.
- Эту инструкцию надо положить в README и в описание релиза.
- Проверено (v0.0.1, 2026-10-20): сборка из GitHub Actions, скачанная браузером, после «Open Anyway»
  запускается, и Quick Look-превью работает. Осталось подтвердить на чистом Mac коллеги.
- Автообновление в v1 нет: новая версия скачивается вручную с GitHub.
